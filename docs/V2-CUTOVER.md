# v2 cutover

What has to happen, in what order, to get the v2 contracts onto testnet without
breaking the thing that currently works.

Status: **nothing here has been done.** This is the plan, written while the
changes are fresh, because the failure mode it describes is silent.

---

## The cliff

The v2 work so far is deliberately **Rust-only**. No TypeScript, `bindings/`,
`packages/sdk` or `deployments/` file has been touched, which is why the live
marketplace still works while five branches of contract changes sit beside it.

That protection ends the moment bindings are regenerated.

`bindings/` is generated from the contract wasm. Regenerating it produces
clients shaped like **v2** — `deposit(cert_id, amount)`, `attest(auditor,
cert_id, allocation)`, `resolve_by_arbiter(id, fraud_proven, harm)` — while
`deployments/testnet.json` still points at **v1** contracts that take the old
shapes. Every SDK read and write then targets an ABI the deployed contracts do
not have.

Concretely, the moment bindings regenerate and before v2 is deployed:

- `packages/sdk` fails to typecheck or silently calls wrong arities
- `listCertificates` / `getCertificate` break, so `/app` on bound-web breaks
- `buildActionXdr("attest", …)` builds envelopes the live registry rejects

So this is **a cutover, not an increment.** Bindings regeneration and deployment
have to land together, and the SDK version that ships against v2 must be a new
major.

There is no upgrade path on any deployed contract — no setters, peer addresses
frozen at `initialize` — so v2 is a deploy to **new addresses**, and `deployments/`
is regenerated by the deploy script, never hand-edited.

## What changed, contract by contract

Everything below is a breaking ABI change unless marked additive.

### Registry

- `attest(auditor, cert_id, allocation)` — **new third argument.** The auditor
  prices their own risk; the contract enforces `min_stake ≤ allocation ≤ free_stake`.
- Additive getters: `get_cert_operator`, `get_cert_expires_at`,
  `get_cert_settlement_deadline`, `get_cert_bound`, `get_cert_agent`,
  `is_cert_verified`.
- `pub const CHALLENGE_WINDOW_SECONDS` (7 days).
- `publish` is unchanged in shape.

### ReserveVault — every function changed

- `initialize(registry, challenge_manager, token)` — **no longer takes an
  operator or a global unlock.**
- `deposit(cert_id, amount)`, `get_balance(cert_id)`, `is_locked(cert_id)`,
  `get_unlock_at(cert_id)`, `release_to_operator(cert_id)` — all now keyed by
  certificate.
- `release_to_victim` → **`pay_from_reserve(cert_id, to, amount)`**.
- `set_cert(cert_id, operator, expires_at)` — snapshots the operator and
  deadline so the hot path does not call the Registry.

### AuditorStaking

- **`slash(auditor, recipient, amount)` is REMOVED.** An arbitrary recipient was
  the vulnerability. Replaced by `slash_allocation(cert_id, treasury, amount)`.
- **`lock` is REMOVED**; `release(auditor)` now withdraws **free stake only**.
- New: `allocate(auditor, cert_id, amount, until)`, `retire_allocation(cert_id)`,
  `release_allocation(cert_id)`, `get_free_stake`, `get_allocated`,
  `get_allocation`, `get_allocation_auditor`, `allocation_unlock_at`.
- `is_registered` now judges **free** stake, not total.

### ChallengeManager

- `initialize` takes **9 arguments** — adds `arbiter`, `treasury`, `min_stake`.
- `resolve_by_arbiter(challenge_id, fraud_proven, harm)` — **new third argument.**
- New: `set_router`, `get_router`, `get_treasury`, `get_bounty_pool`,
  `get_bonds_held`.

### PaymentRouter — entirely new

A SEP-41 token (`bUSDC`) wrapping USDC and metering spend per certificate. Needs
its own bindings entry, its own `deployments/` key, and an SDK surface.

## Order of operations

The order matters; steps 3 and 4 are the ones that bite.

1. **Merge the stack** (`bound` PRs #10 → #15, then `feat/trustless-predicates`),
   bottom-up. Everything is still Rust-only at this point and nothing breaks.

2. **Update `scripts/deploy-all.ts`.** It currently deploys five contracts and
   initializes them. It must now:
   - deploy `payment_router` as a sixth (`fee_escrow` is still deployed but is
     not on the settlement path);
   - pass the new `ChallengeManager.initialize` arguments — **decide the treasury
     and arbiter addresses before this point**, because there is no admin and
     nothing can be repointed afterwards;
   - call **`ChallengeManager.set_router(router)`** and
     **`PaymentRouter.initialize(registry, token)`**.

   **`set_router` is the trap.** It is one-shot and arbiter-gated, and nothing
   calls it today. A deployment that skips it resolves both `BoundExceeded` and
   `ExpiredCertificate` into `router_not_set` — the two proofs this whole
   milestone exists to enable, silently dead, with every other test passing.

3. **Regenerate `bindings/`** — this is the cliff. From here the SDK is v2-only.

4. **Deploy to testnet.** New addresses; `deployments/testnet.json` is rewritten
   by the script.

5. **Update `packages/sdk`** for the new shapes and add the router. Ship as
   **0.3.0** at minimum — this is not a patch. `attest` gains an argument,
   `depositReserve` gains a certificate, `reserveBalance()` gains a certificate.

6. **Update bound-web.** `lib/bound.ts` and `lib/tx.ts` are the only two modules
   that touch the SDK, which is what makes this survivable. `/app/new` can drop
   the "an arbitrary operator cannot fund a reserve" disclosure, because on v2
   they can.

7. **Re-run the seed/demo flow** so the marketplace has live, unexpired
   certificates. Today's six all expired on 2026-07-03.

8. **Update `bound-docs`.** The five-defect disclosure describes the _deployed_
   contracts; once v2 is live, L1–L5 move from "live" to "fixed in this
   revision", and the trust-model reconciliation about the reserve check being
   pooled comes out.

---

## What does not change

- `publish` still authenticates only the operator and still overwrites the
  agent-to-certificate mapping. **L1 is not fixed by any of this work.**
  Enumerating by certificate id remains mandatory, in the SDK and anywhere else.
- No TTL management anywhere. **L2 is not fixed.** A v2 deployment is on the same
  archival clock as v1.
- FeeEscrow's one-shot release. **L3 is not fixed**; it is simply not on the
  settlement path.

Anyone reading this as "v2 fixes the five defects" should stop: it fixes L5 and
L4-adjacent issues. L1, L2 and L3 are still open and still belong in the
disclosure.

---

## Rollback

There is none in the contract sense — no upgrade path, no admin, no migration of
v1 state. Rollback means repointing `deployments/testnet.json` at the v1
addresses and shipping the previous SDK major. Keep the v1 addresses in the
deployment record's history rather than deleting them.
